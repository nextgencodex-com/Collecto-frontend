# Collecto-frontend

Next.js frontend for **COLLECTO** — smart installment & collection management for a retail shop.
Two apps in one project:

- **Owner / admin** (desktop-first): dashboard, customers, installments, products, inventory, riders,
  collections, reports, audit log, settings.
- **Rider** (mobile, `/rider`): today's visits, map, customers, collect payment, receipts, daily closing,
  history, profile.

## Stack

Next.js 16 (App Router, TypeScript) · Tailwind CSS v4 · Radix UI (shadcn/ui-style primitives) · Zustand · Sonner

## Getting started

```bash
npm install
npm run dev
```

Open http://localhost:3000 and sign in with a demo account:

| Role  | Username             | Password   |
| ----- | -------------------- | ---------- |
| Owner | `owner@collecto.lk`  | `owner123` |
| Rider | `kasun`, `nimal` or `tharindu` | `1234` |

Data now comes from the Collecto backend (`../Collecto-backend`). Start it first (see its README), then copy
`.env.example` to `.env.local` and `npm run dev`. "Today" is the current date in the shop's time zone
(`NEXT_PUBLIC_APP_TZ`, default `Asia/Colombo`); set `NEXT_PUBLIC_DEMO_TODAY` to pin it, and the backend's
`APP_TODAY` to the same date.

The demo accounts above exist only if the backend was seeded (`npm run db:seed` there), and the demo credentials,
pre-filled login form and **Settings -> Reset demo data** are shown in development builds only.

## Project structure

```
src/
  app/
    login/                 sign-in (owner / rider tabs)
    (owner)/…              owner pages, wrapped in the sidebar + topbar shell
    rider/…                rider mobile app with bottom tab bar
  components/
    layout/owner|rider/    app shells
    modals/                customer, item, product, stock, rider, correction, receipt dialogs
    ui-collecto/           shared UI primitives (chips, avatar, tables, search, pager, …)
  lib/
    calc.ts                installment schedule / balance engine
    seed.ts                demo dataset
    selectors.ts           derived data, dashboard & report builders
  store/                   Zustand client cache of the server data (+ session) and the UI modal store
  services/http.ts         fetch client: in-memory access token, refresh-cookie, one retry on 401
  services/api.ts          API facade: every write goes to the backend, then the store re-syncs
scripts/extract-prototype.mjs   unpacks the original COLLECTO.html prototype into reference/ + assets
reference/                 readable sources of the HTML prototype (porting reference only)
```

## Backend integration

- `NEXT_PUBLIC_API_URL` (default `http://localhost:4000/api/v1`) is the API base URL.
- After sign-in the store loads everything from `GET /bootstrap` (scoped to the role) and `api.ts` re-syncs it after
  each write, so pages keep reading `useDerived()` / `useAppStore` exactly as before.
- Sessions: the access token is kept in memory; the refresh token is an httpOnly cookie. On a 401 the client refreshes
  once and retries; if that fails the user is signed out. A page reload restores the session from the cookie.
- Money is handled in paise: inputs accept up to 2 decimals, and `calc.ts` rounds every sum to paise.
- Reports are generated by the backend (`GET /reports/:type`); the CSV is built from that response.
- The backend's `CORS_ORIGINS` must include this app's origin, and the cookie settings (`COOKIE_SAMESITE`,
  `COOKIE_SECURE`) must suit how the two are hosted (same site: `lax`; different sites: `none` + HTTPS).
- API documentation: `<backend>/api/docs` (Swagger UI), available outside production.
